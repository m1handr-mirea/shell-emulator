# Эмулятор командной строки UNIX-подобной ОС

Консольное приложение (CLI) на языке C++ (стандарт C++17), эмулирующее работу командной строки UNIX-подобной операционной системы с поддержкой виртуальной файловой системы (VFS), функционирующей исключительно в оперативной памяти.

## 📝 Отчет о выполненной работе по этапам

### Этап 1. REPL и минимальный прототип
- **Цель:** создать консольный интерфейс приложения, базовый цикл REPL (Read-Eval-Print Loop), парсер аргументов командной строки и команды-заглушки.
- **Реализованная функциональность:**
  - Реализован класс `ShellEmulator`, обеспечивающий диалоговый цикл с пользователем.
  - Приглашение к вводу (Prompt) содержит имя виртуальной файловой системы (по умолчанию `default_vfs`).
  - Разработан парсер командной строки `ShellEmulator::parseCommandLine`, корректно обрабатывающий аргументы в одинарных (`'...'`) и двойных (`"..."`) кавычках с сохранением пробелов внутри них, а также экранирование символов (`\`).
  - Реализована обработка ошибок: синтаксическая ошибка при незакрытых кавычках, сообщение о неизвестной команде и неверном числе аргументов.
  - Реализованы команды-заглушки `ls` и `cd`, выводящие имя вызванной команды и список полученных аргументов.
  - Реализована команда `exit` для корректного выхода из эмулятора.
- **Тестирование:** подготовлен скрипт `scripts/demo_stage1.sh`, демонстрирующий интерактивный ввод, обработку кавычек и ошибки.

### Этап 2. Конфигурация эмулятора
- **Цель:** сделать эмулятор настраиваемым с помощью параметров командной строки и поддержать выполнение команд из файла стартового скрипта.
- **Реализованная функциональность:**
  - Поддержаны параметры командной строки:
    - `-v`, `--vfs <путь>` — физический путь к JSON-образу VFS;
    - `-s`, `--script <путь>` — путь к стартовому скрипту команд;
    - `-h`, `--help` — вывод справки по параметрам запуска.
  - Организован отладочный блок (`[DEBUG]`) при запуске эмулятора с выводом всех переданных параметров.
  - Реализовано выполнение команд из стартового скрипта:
    - Поддерживаются однострочные комментарии с синтаксисом C++ (`//`);
    - Имитируется живой диалог с пользователем: перед выполнением команды на экран выводится приглашение к вводу (`[vfs]$ command`), а затем результат её выполнения.
- **Тестирование:** созданы скрипты реальной ОС `scripts/run_stage2_*.sh` для проверки запуска без аргументов, только с VFS, только со скриптом, со всеми параметрами и с ошибочными аргументами.

### Этап 3. Подключение виртуальной файловой системы (VFS)
- **Цель:** реализовать загрузку VFS из внешнего файла JSON в оперативную память и предоставить служебную информацию о ней.
- **Реализованная функциональность:**
  - Структура данных VFS хранится строго в оперативной памяти (класс `VirtualFileSystem`, узлы `VfsNode`). Исходный файл на диске не модифицируется и не распаковывается.
  - Написан встроенный парсер JSON (`JsonValue`), разбирающий иерархическое дерево каталогов и файлов.
  - Поддержана загрузка двоичных данных файлов с представлением в формате Base64 (`Base64::decode`).
  - Реализован алгоритм вычисления хеша SHA-256 по стандарту FIPS 180-4 (`Sha256`), вычисляющий контрольную сумму исходного файла VFS (результат совпадает со стандартной системной утилитой `shasum -a 256`).
  - Реализована служебная команда `vfs-info`, выводящая имя загруженной VFS, SHA-256 хеш данных и общее количество узлов в памяти.
  - Приглашение к вводу динамически отображает имя загруженной VFS.
- **Тестирование:** подготовлены образы VFS `tests/vfs_minimal.json` (1 файл), `tests/vfs_multiple.json` (несколько файлов и папок) и `tests/vfs_deep.json` (глубина вложенности более 3 уровней), а также скрипты проверки `scripts/test_stage3_*.sh`.

### Этап 4. Основные UNIX-подобные команды
- **Цель:** реализовать логику стандартных команд для навигации и чтения файлов VFS.
- **Реализованная функциональность:**
  - `ls [путь...]` — вывод списка файлов и подкаталогов текущей или указанной директории (каталоги помечаются символом `/`).
  - `cd [путь]` — смена текущего рабочего каталога. Поддерживаются относительные и абсолютные пути, навигация по `.`, `..` и `/`. Приглашение ко вводу отражает текущий рабочий путь (`[vfs:/path]$`).
  - `echo [аргументы...]` — вывод переданных аргументов в консоль через пробел с сохранением закавыченных подстрок.
  - `cat <файл...>` — вывод текстового или декодированного Base64 содержимого файлов в стандартный поток вывода.
  - `tail [-n N] <файл>` — вывод последних N строк файла (по умолчанию 10 строк, поддерживается флаг `-n`).
  - Полноценная обработка ошибок для всех команд (файл/каталог не найден, попытка перехода в файл, передача каталога в `cat`/`tail` и др.).
- **Тестирование:** разработан сценарий `scripts/startup_stage4.txt` и скрипт `scripts/test_stage4.sh`, проверяющие все режимы работы команд и граничные случаи.

### Этап 5. Дополнительные команды и модификация VFS
- **Цель:** поддержать команды, изменяющие состояние VFS в памяти, и предоставить справочную систему.
- **Реализованная функциональность:**
  - `mkdir [-p] <каталог...>` — создание каталогов в памяти VFS. Флаг `-p` позволяет создавать цепочки промежуточных родительских каталогов и не возвращает ошибку, если каталог уже существует.
  - `mv <источник> <назначение>` — перемещение и переименование файлов и каталогов в памяти VFS. Встроена проверка на предотвращение перемещения каталога внутрь самого себя.
  - `help [команда]` — вывод общего списка доступных команд с кратким описанием либо подробной справки по конкретной команде.
  - Все операции по изменению структуры VFS осуществляются строго в оперативной памяти (указатели `shared_ptr`).
- **Тестирование:** сценарий `scripts/startup_stage5.txt` и скрипт `scripts/test_stage5.sh`. Скрипт фиксирует хеш SHA-256 файла VFS на диске до запуска и после завершения работы эмулятора, подтверждая полную неизменность исходных данных на диске.

│   ├── sha256.h / sha256.cpp   # Вычисление хеша SHA-256 (FIPS 180-4)
│   └── base64.h / base64.cpp   # Кодирование и декодирование Base64
├── tests/                      # Примеры образов VFS

│   ├── vfs_multiple.json       # Образ с несколькими файлами и папками
│   └── vfs_deep.json           # Образ с вложенностью более 3 уровней
└── scripts/                    # Тестовые скрипты и сценарии запуска
    ├── demo_stage1.sh          # Тестирование Этапа 1 (REPL, парсинг)
    ├── run_stage2_*.sh         # Тестирование параметров CLI (Этап 2)
    ├── test_stage3_*.sh        # Тестирование загрузки VFS (Этап 3)
    ├── test_stage4.sh          # Тестирование основных команд UNIX (Этап 4)
    ├── test_stage5.sh          # Тестирование модификаций VFS (Этап 5)
    └── startup_stage*.txt      # Сценарии команд для эмулятора

## ⚙️ Параметры командной строки

```bash
./shell_emulator [ПАРАМЕТРЫ]

Параметры:
  -v, --vfs <путь>      Физический путь к JSON-образу VFS
  -s, --script <путь>   Путь к стартовому скрипту команд для выполнения
  -h, --help            Показать справку по параметрам запуска
```

### Примеры запуска:
```bash
# Интерактивный режим
./shell_emulator

# Запуск с образом VFS
./shell_emulator --vfs tests/vfs_deep.json

# Запуск с выполнением стартового скрипта
./shell_emulator --vfs tests/vfs_deep.json --script scripts/startup_stage5.txt
```

## 💻 Поддерживаемые команды

| Команда | Описание | Пример |
|---|---|---|
| `ls [путь...]` | Вывод содержимого каталогов (каталоги помечаются `/`) | `ls`, `ls var/log` |
| `cd [путь]` | Переход в директорию (поддерживаются `.`, `..`, `/`) | `cd home/student`, `cd ..` |
| `echo [аргументы...]` | Вывод строки в консоль с учетом кавычек | `echo "Привет, мир"` |
| `cat <файл...>` | Просмотр содержимого текстовых и Base64 файлов | `cat root_file.txt` |
| `tail [-n N] <файл>` | Вывод последних N строк файла (по умолчанию 10) | `tail -n 2 app.log` |
| `mkdir [-p] <путь>` | Создание каталога в памяти (-p для промежуточных папок) | `mkdir -p a/b/c` |
| `mv <источник> <цель>` | Перемещение или переименование файла/папки в VFS | `mv file.txt dir/` |
| `vfs-info` | Вывод имени VFS, SHA-256 хеша и количества узлов | `vfs-info` |
| `help [команда]` | Вывод справки по доступным командам | `help`, `help mkdir` |
| `exit` | Завершение работы эмулятора | `exit` |
